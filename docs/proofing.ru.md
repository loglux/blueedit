# Орфография и грамматика в BlueEdit

*In English: [proofing.md](proofing.md)*

Установка всех компонентов — скриптом или вручную: [proofing-setup.ru.md](proofing-setup.ru.md).

Проверка состоит из двух независимых частей:

| | Что ищет | Кто проверяет | Где включается |
|---|---|---|---|
| **Орфография** | слова с опечатками | словари Windows, Microsoft Word или Hunspell | F8, **Tools → Spelling provider…** |
| **Грамматика** | согласование, пунктуация, неверные слова в контексте | LanguageTool, языковая модель (здесь, на сервере моделей или в облачном сервисе), Harper, корректор Edge или Chrome — любые вместе | **Tools → Grammar checking…** |

Они работают одновременно: опечатки подчёркиваются одним цветом, грамматика — другим. Всё проверяется на вашем
компьютере, и текст никуда не отправляется, если только для грамматики не выбран сервер моделей в другом месте или
облачный сервис: тогда проверяемые абзацы уходят туда.

## Клавиши

| Клавиша | Что делает |
|---|---|
| **F7** | на подчёркнутом месте — варианты исправления |
| **Shift+F7** | к следующей ошибке (выделяет её, дальше F7) |
| **Tools → Previous problem** | к предыдущей |
| **F8** | включить / выключить орфографию |
| **Tools → Grammar model…** | какой моделью проверять грамматику (и стиль) |
| **Ctrl+F7** | предложения по стилю для абзаца под курсором |
| **Tools → Style options…** | что искать в стиле |

### Кто нашёл ошибку

Каждая находка подписана источником:

- окно F7 на опечатке: `"превет" — Windows spelling` (или `Office spelling`, `Hunspell spelling`);
- окно F7 на грамматике: заголовок `LanguageTool: Неверное спряжение…`, у каждого варианта — кто его предложил:

  ```
  LanguageTool: Неверное спряжение глагола или неверное местоимение
    пошёл   — Gemma 3 12B: Глагол согласуется с «я»
    [ Ignore ]   (until the editor closes)
    [ Never show this ]
  ```

  В строке сообщений ещё видно правило LanguageTool и его категорию, например `[RU_VERB_CONJUGATION · GRAMMAR]`.

- строка состояния после Shift+F7: `Spelling (Windows): speling`, `Grammar (LanguageTool): …`,
  `Grammar (Gemma 3 12B): …`.

Если на одном месте сработали несколько проверяльщиков, F7 показывает варианты от всех. Бывает, что один только
объясняет ошибку (LanguageTool часто так делает), а исправление даёт другой.

## Орфография

### Поставщик: Windows, Office или Hunspell

**Tools → Spelling provider…**

- **Windows** (по умолчанию) — словари, встроенные в Windows. Мгновенно, ничего ставить не надо.
- **Office** — словари Microsoft Word. Нужен установленный Word; он запускается скрыто в фоне, первые слова
  проверяются на пару секунд дольше. Словари у Word полнее (больше терминов, имён, редких форм).
- **Hunspell** — словари LibreOffice и Firefox (`ru_RU.dic` + `ru_RU.aff`), их читает
  [WeCantSpell.Hunspell](https://github.com/aarondandy/WeCantSpell.Hunspell) — перенос Hunspell на C# внутри BlueEdit.
  **Единственный поставщик на Linux и macOS**, со словарями системы (`apt install hunspell-ru hunspell-en-gb`) или
  из **Tools → Get spelling dictionaries…** (словари LibreOffice, скачиваются без root);
  на Windows читает `%LOCALAPPDATA%\BlueEdit\hunspell`. Словари загружаются в фоне (меньше полсекунды для русского и
  английского, замерено в WSL), пока они грузятся, ничего не подчёркивается. Проверено на Linux (WSL Ubuntu 24.04 с
  её hunspell-ru и hunspell-en-gb); на Windows пока только с тестовым словарём.

### Языки

**Tools → Spelling languages…** — галочками отметить нужные языки. Режим **auto** берёт языки, добавленные в Windows
(Параметры → Время и язык → Язык и регион). Если нужного языка в списке нет — добавьте его в Windows (для Office —
установите языковой пакет Office). На Linux и macOS **auto** берёт языки локали (`LANGUAGE`, иначе `LC_ALL`,
`LC_MESSAGES` или `LANG`: `de_DE.UTF-8` → `de-DE`). Если система не называет ни одного (локаль `C` на сервере), берётся
список из настроек — по умолчанию английский (`en-US`).

Английский: `en-GB` и `en-US` — разные словари (colour/color, organise/organize), выбирайте нужный.

Слово в буквах, которыми не пишется ни один из языков проверки (русское при одном английском), не подчёркивается: оно
не проверено, а не ошибочно. F7 на нём так и скажет.

### Язык абзаца

Грамматика и предложения по стилю проверяют каждый абзац на его языке, выбранном среди языков орфографии:

- **Сначала по буквам**: кириллица, латиница, греческие, арабские... Для русского и английского этого достаточно.
- **Языки с одними буквами** (английский и немецкий, русский и украинский) различает модель определения языка
  fastText (176 языков, встроена в редактор, без сети): ответы те же, что у самого fastText, около 0,1 мс на абзац.
  Сначала отсеиваются языки, в которых нет буквы из текста («ы» нет ни в украинском, ни в болгарском).
- **Короткая строка** (заголовок, пара слов) слишком коротка, чтобы судить: она получает язык, на котором написано
  большинство длинных абзацев документа.
- **Markdown-документ может сам назвать свои языки** в начале, как заметки Obsidian, и это главнее:

  ```
  ---
  language: de
  ---
  ```

  (или `lang:`; несколько: `language: de, en`). `de` проверяется как ваш язык орфографии `de-DE`, если он есть.
- Текст в алфавите, которого нет ни у одного вашего языка (русский, когда отмечен только английский), угадывается
  среди распространённых языков, иначе язык определяет сам LanguageTool.

Языковой модели язык абзаца называется прямо. Замерено только на русском и английском; для других языков модель
получает те же указания с названием языка, без подстройки под него. Орфография по-прежнему принимает слово, если его
знает любой из ваших языков.

### Свой словарь

**F7 → Add to dictionary** добавляет слово в `%APPDATA%\blueedit\dictionary.txt` — одно слово в строке, файл можно
править вручную. Словарь общий для всех поставщиков орфографии (Windows, Word, Hunspell). **F7 → Ignore** пропускает слово до закрытия редактора.

### Что не проверяется

Адреса сайтов, e-mail, пути к файлам, код и блоки кода. Слово, набранное частично в другой раскладке («пpивет» с
латинской p), отмечается всегда; F7 предлагает его в одном алфавите.

## Грамматика

**Tools → Grammar checking…** — галочками выбрать проверяльщиков (любые вместе или ни одного). Не установленные
помечены `(not installed)`, при выборе показывается, что и куда поставить. Работает в Markdown, LaTeX и простом тексте.

Абзац уходит на проверку, когда его не правили около полутора секунд, поэтому подчёркивание появляется с небольшой
задержкой, а не во время набора. Проверяльщики запускаются при первой проверке (несколько секунд — в строке состояния
`GRAMMAR LT+LLM starting`) и закрываются вместе с редактором.

**Текст с формулами** (Markdown с `$…$` и `$$…$$`, как в Obsidian): проверяльщики читают предложение вокруг формулы,
но внутри формулы ничего не подчёркивается и не меняется — ни грамматикой, ни советами по стилю. Выносная формула —
часть предложения вокруг неё, с пустыми строками или без: «подставляя, получаем ⏎⏎ $$…$$ ⏎⏎ где S — площадь»
проверяется как одно предложение — формула присоединяется к незаконченному тексту (без точки в конце), а текст после
неё, продолжающийся со строчной буквы, тоже; запятая или точка после формулы проверяется. Замер на работах по
математике: языковые модели нашли все ошибки, вставленные рядом с формулами, и ничего не отметили в правильных
предложениях (подробно — [docs/tech/proofing-internals.md](tech/proofing-internals.md#formulas-markdown)). `\(…\)` и `\[…\]` —
тоже формулы, `\[` на несколько строк — когда стоит в начале строки. Две формулы подряд, `$a$$b$`, — две, как их
рисует Obsidian.

### Ошибки в формулах

Формула, которая не наберётся, подчёркивается как ошибка, так же как ошибки языкового сервера: **Shift+F7** переходит
к ней, **F7** говорит, что не так, строка состояния их считает (`TeX 2E`). Без модели и без установки: редактор
читает формулу сам. Находит то, на чём останавливаются MathJax (Obsidian) и LaTeX, словами MathJax:

- скобка, `\left`, `\begin{…}` без парной, или `\begin{aligned}`, закрытый `\end{array}`;
- команда без аргументов: `\frac{a}`, `\sqrt`, `x^`;
- `x^2^3` или `x_1_2` («use braces to clarify»), `&` вне `aligned`, `array` и подобных, `\left{`.

Незнакомые команды не отмечаются: документ может определить свои. Файлы Markdown: `$…$`, `$$…$$` (и на несколько
строк), `\(…\)`, `\[…\]`, не в коде; файлы LaTeX: пока только формулы внутри строки, без выносных окружений.
Замер на 726 заметках по математике (около 134 000 формул): 18 находок, 16 из них — формулы, потерявшие
`\begin{aligned}` при переводе из Word, 2 — в программном коде вне блока кода, который и Obsidian считает формулой.
Выключается в **Tools → Settings → Formula errors** (`latexCheck`).

**Правила записи**, как у [chktex](https://www.nongnu.org/chktex/): формула набирается, но не так, как задумано.
Каждая находка — предупреждение (`TeX 1W`); **F7** подставляет исправление или, через *Never show this*, выключает
это правило (вернуть: Tools → Ignored rules):

| Правило | Написано | Получается | Исправление |
|---|---|---|---|
| `latex-function` | `cos x`, `ln(y)` | буквы c·o·s курсивом | `\cos x` |
| `latex-function-braces` | `\cos{(x)}` | пробел между cos и скобкой | `\cos(x)` |
| `latex-times` | `2*3`, `x * 4` | звёздочка | `\times` |
| `latex-operator` | `<=`, `>=`, `->`, `=>`, `<=>` | два знака | `\le`, `\ge`, `\to`, `\Rightarrow`, `\Leftrightarrow` |
| `latex-dots` | `1, 2, ..., n` | три точки | `\dots` |
| `latex-unit` | `5 cm`, `12kg` | единица курсивом, как произведение букв | `5\,\text{cm}` |

Не отмечаются, потому что верны: `x_{max}` (подпись), `z^*`, `f * g` (без числа), `x<-1`, `n!=120`, однобуквенная
единица вроде `2m` (это так же часто переменная). Замер на тех же заметках: 92 предупреждения, из них 2 ложных (таблица
клавиш калькулятора, где `*` и имеется в виду, и текст, который не формула); остальные настоящие:
`\cos{(\angle DEF)}`, `cos\ 28^{\circ}`, `5.536\ km`, `2*5*0.2`, `233.333...`. Все разом выключаются в
**Tools → Settings → Formula style hints** (`latexStyle`).

### LanguageTool

Бесплатная версия [LanguageTool](https://languagetool.org) с открытым кодом, работает как локальный сервер (не
платный облачный сервис). Правила, а не нейросеть: объясняет каждую находку, хорошо ловит пары слов («одеть/надеть»),
но часто не предлагает исправление. Около 0,7–1 ГБ памяти, пока работает.

Установка — в `%LOCALAPPDATA%\BlueEdit\`:

```
jre\            Java 21 JRE — zip Eclipse Temurin с adoptium.net, распаковать
languagetool\   LanguageTool-stable.zip с languagetool.org, распаковать
```

Другое место — настройка `languageToolDir`.

### Языковая модель

Открытая нейросеть на сервере [llama.cpp](https://github.com/ggml-org/llama.cpp), работает как корректор: возвращает
исправленный текст с короткими пояснениями, редактор сравнивает его с вашим и подчёркивает отличия. Хорошо находит
согласование и запятые («Мы был», «сказал, что», «results was») и сразу предлагает исправление. Если модель
переписала абзац вместо исправления, её ответ отбрасывается. Английский проверяется с британской орфографией, а с
американской — когда ваш язык проверки английского `en-US` (до 0.2.9 американский текст тоже проверялся на британскую
орфографию, и модели «исправляли» color, center, analyzed).

Установка — в `%LOCALAPPDATA%\BlueEdit\llm\`:

```
bin\            llama.cpp для Windows: zip CUDA (NVIDIA) или Vulkan из GitHub releases, распаковать
models\         файл модели .gguf
```

Проверенные модели (квантование Q4_K_M):

| Модель | Видеопамять | Где взять (Hugging Face) |
|---|---|---|
| **YandexGPT 5 Lite 8B** | ~6 ГБ | `yandex/YandexGPT-5-Lite-8B-instruct-GGUF` — лучшая в русском |
| **Gemma 3 12B** | ~8 ГБ | `bartowski/google_gemma-3-12b-it-GGUF` — сильная в обоих языках |
| Qwen3 8B / 14B | ~6 / ~10 ГБ | `Qwen/Qwen3-8B-GGUF`, `bartowski/Qwen_Qwen3-14B-GGUF` |
| Gemma 3 4B | ~3 ГБ | `bartowski/google_gemma-3-4b-it-GGUF` — для слабых видеокарт |
| Phi-4-mini | ~3 ГБ | `bartowski/microsoft_Phi-4-mini-instruct-GGUF` — самая быстрая |

Подробное сравнение — ниже, в разделе «Сравнение: кто точнее». Модель выбирается в **Tools → Grammar model…**:
список всех установленных и **Auto** — лучшая из них по замеру (YandexGPT 5 Lite, затем Gemma 3 12B, Qwen3 8B,
Qwen3 14B, Gemma 3 4B, Phi-4-mini). Выбор сохраняется в `llmModel`. Ответ — 0,2–1 с на абзац на
видеокарте среднего класса. Другое место — `llmDir`.

#### Сервер моделей по адресу (Ollama, LM Studio, другой компьютер, облачный API)

Первый выбор — llama.cpp на этом компьютере, его запускает сам редактор. Сервер по адресу — второй выбор и запасной
путь: всё, что понимает chat completions OpenAI, — Ollama, LM Studio, llama-server на компьютере с видеокартой в
сети, облачный API. В файле настроек:

```jsonc
"llmServer": "http://127.0.0.1:11434/v1",   // Ollama здесь; или http://192.168.1.20:8080 (llama-server), https://api.openai.com/v1
"llmServerModel": "qwen3.5:9b",             // имя модели там
"llmApiKey": "env:OPENAI_API_KEY",          // ключ, если серверу нужен: как есть, "env:ИМЯ" или "file:ПУТЬ" (например file:~/key.txt)
```

**Облачные сервисы** редактор спрашивает каждый по-своему, так, как лучше всего сработало у плагина [BlueProof](https://github.com/loglux/obsidian-blueproof) для
Obsidian, поэтому достаточно адреса (и ключа, и модели):

| Сервис | `llmServer` | С какой моделью пробовали |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-5.4-mini` |
| Anthropic (Claude) | `https://api.anthropic.com/v1` — своё API, не форма OpenAI | `claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-haiku-4-5` |
| Google (Gemini) | `https://generativelanguage.googleapis.com/v1beta` — своё API; `…/v1beta/openai` — его форма OpenAI | `gemini-3.5-flash-lite` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-flash`, `deepseek-v4-pro` |

23 октября 2026 года каждый ответил через код самого редактора и нашёл ошибку в английском и русском абзаце, за 1–2,5 с
(`CloudCheck`, `docs/tech/proofing-internals.md`); насколько хорошо каждый справляется на множестве текстов, замерял
плагин ([его docs/servers.md](https://github.com/loglux/obsidian-blueproof/blob/main/docs/servers.md)). Другой сервис с API как у OpenAI тоже может подойти: от чего он отказывается, редактор
узнаёт из его ответов. **Tools → Set up grammar checking → Another model server** проверяет сервер, прежде чем
сохранить (его список моделей: отвечает ли, принимает ли ключ, есть ли модель), говорит, что не так, и по просьбе
сохраняет всё равно. Если модель не названа (установщик не называет её для Ollama, LM Studio и llama-server), редактор
берёт первую из списка сервера; **Tools → Grammar model** выбирает другую. Из файла ключа в несколько строк (два ключа)
берётся первая. Если ключ не принят, так и
сказано; при лимите запросов сервиса строка состояния говорит, до какого времени, до тех пор ничего не отправляется, а
абзацы проверяются потом.

**Tools → Grammar model…** тогда показывает модели сервера под файлами `.gguf` этого компьютера; выбор такой модели
ставит `llmModel` в `"server"`. Если выбрана локальная модель (или Auto), сервер используется, только когда здесь нет
llama.cpp или модели или llama.cpp не запустился, и строка состояния об этом говорит. Грамматика и стиль идут туда оба.

- **Приватность**: адрес вне этого компьютера и локальной сети (не `127.x`, `10.x`, `192.168.x`, `172.16–31.x`, не
  простое имя и не `.local`) значит, что абзацы уходят с компьютера; строка состояния при запуске говорит куда.
- Чего сервер не принимает, редактор узнаёт из его же ответа (`400 Unknown parameter: '…'`) и больше не посылает:
  `chat_template_kwargs` llama.cpp (OpenAI его отвергает), `temperature` (отвергают модели с рассуждениями),
  `max_tokens` (там, где нужно, — `max_completion_tokens`). «Размышления» выключаются `reasoning_effort: "none"`: через
  Ollama без этого Qwen тратил весь лимит ответа на рассуждения и не отвечал ничем (нашёл плагин для Obsidian).
- **Ключ**, введённый в **Tools → Set up grammar checking → Another model server**, сохраняется в отдельный файл
  `llm-key` рядом с `settings.json`, а в настройках остаётся только `"file:llm-key"`: ключ не виден, когда настройки
  открыты, и не попадает в их копию. В Windows файл зашифрован DPAPI — встроенным средством системы для сохранённых
  паролей: прочесть его может только этот пользователь на этом компьютере. В Linux это обычный текст, который может
  читать только этот пользователь (права 600). `env:ИМЯ` и ключ, вписанный прямо в настройки, работают как раньше; ключ
  из файла с BOM (Блокнот) очищается от него.
- Находки подписываются моделью, которая ответила (llama-server отвечает своей моделью, какое бы имя ни спросили).
- **Первая загрузка в Ollama может длиться минуты**, а если запрос, ждущий её, закрыть, Ollama бросает загрузку;
  редактор ждёт ответа 5 минут (предложение стиля держит экран, пока ждёт). Замер 6 октября 2026: первый запрос к
  `qwen3.5:9b` — 6 мин 45 с, следующие — около секунды. Новую модель загрузите один раз вручную
  (`ollama run qwen3.5:9b`), прежде чем пользоваться ею здесь.

Замер через редактор (`ProofBench`, британский академический набор) 6 октября 2026: **qwen3.5:9b через Ollama на этом
компьютере** нашла 24 из 24 грамматических ошибок, 2 из 3 пунктуационных, 7 из 8 в написании, одна ложная тревога
(«learnt» → «learned»), 0,96 с на предложение — больше всех моделей на этом наборе (Gemma 3 12B в llama.cpp: 23, без
ложных тревог, 1,1 с). Одни и те же веса через Ollama и llama.cpp не сравнивались: `qwen2.5` из Ollama не загрузилась в
этой сборке llama.cpp (остановилась на чтении словаря).

### Корректор Edge (экспериментально)

Встроенный корректор Microsoft Edge — небольшая модель Aion, работает на вашем компьютере, только английский.
Официально он ещё не включён: редактор запускает скрытый Edge Canary со своим профилем и скрытыми флагами, которые его
включают, и передаёт ему абзацы. Ваш обычный Edge и его профиль не затрагиваются. Находки подписаны «Edge».

Нужен [Edge Canary](https://www.microsoft.com/edge/download/insider) (или другой Edge с этим корректором — путь к
`msedge.exe` в настройке `edgePath`). Модель (~1,2 ГБ) Edge скачивает сам при первом включении, в
`%LOCALAPPDATA%\BlueEdit\edge-profile`; пока она качается, в строке состояния `starting`.

Проверяет по американским правилам: британское написание (organised, centre) считает ошибкой. По замеру он уступает
YandexGPT и Gemma, но оставлен на случай, если Microsoft его улучшит. Способ неофициальный: обновление Edge может его
сломать — тогда в строке состояния будет `GRAMMAR … failed`.

Требования Microsoft к его модели: видеокарта от 5,5 ГБ памяти, не меньше 20 ГБ свободного места на диске с профилем
(если останется меньше 10 ГБ, Edge сам удалит модель), безлимитное подключение для первой загрузки. Подходит ли
компьютер, видно в Edge Canary на странице `edge://on-device-internals` (Device performance class — High или выше).

### Корректор Chrome

Встроенный корректор Chrome: маленькая модель (117 МБ), сделанная под одну эту задачу, только английский. BlueEdit
управляет скрытым Chrome со своим профилем, как и Edge; нужно, чтобы флаги корректора были включены в вашем Chrome
(как — [proofing-setup.ru.md](proofing-setup.ru.md#корректор-chrome)). Находки подписаны «Chrome». Он убирает точку в
конце предложения, которое в остальном не трогает; редактор возвращает её. На британском академическом наборе: 21 из 24
грамматических ошибок, 7 ложных тревог из 24 (британское «committee have», выброшенное «had», заглавные буквы), 0,7 с
на предложение — сильно впереди LanguageTool и Harper, позади моделей, гораздо тише Edge. Chrome выбирает среди самых вероятных ответов случайно: два
прогона набора разошлись в 6 предложениях из 59 (4 и 7 ложных тревог).

**Та же модель без Chrome** («chromemodel», в списке — **Chrome model**): LiteRT-LM от Google запускает файл модели,
который скачал Chrome, — без браузера и без флагов. Установка — `install.ps1 -ChromeModel` (нужен Python 3.10+; он
создаёт виртуальное окружение в `%LOCALAPPDATA%\BlueEdit\litert` и ставит `litert-lm` с PyPI). Модель копируется из
вашего Chrome при запуске проверки, так что Chrome должен был её однажды скачать. На британском академическом наборе:
17 из 24 грамматических ошибок, 2 ложные тревоги (обе — «the committee have» в единственное число), 0,3 с на
предложение на процессоре — находок меньше, чем у самого Chrome (21), ложных тревог гораздо меньше, один и тот же текст
— всегда один и тот же ответ. Видеокарта не нужна: для английского на компьютере без неё находит вдвое больше
LanguageTool и втрое больше Harper.

### Harper

[Harper](https://github.com/Automattic/harper) (Automattic, открытый код): правила для английского, написанные
вручную, — без модели и без видеокарты, отвечает за десятки миллисекунд. Следует варианту языка текста: для `en-GB` —
британскому (colour, organise, programme — верно), для `en-US` — американскому, есть ещё австралийский и канадский.
Находки подписаны «Harper», у каждой есть исправления. Его собственная проверка орфографии выключена: орфография —
дело поставщика проверки орфографии, как и у LanguageTool.

Нужен `harper-ls` (языковой сервер Harper): распакуйте `harper-ls-x86_64-pc-windows-msvc.zip` из его
[релизов](https://github.com/Automattic/harper/releases) в `%LOCALAPPDATA%\BlueEdit\harper` (на Linux —
`…-unknown-linux-gnu.tar.gz` в `~/.local/share/BlueEdit/harper`) или держите `harper-ls` в PATH. Только английский.

### Что выбрать

- **Модель** (YandexGPT 5 Lite или Gemma 3 12B) — находит больше всего, сразу с исправлениями; нужна видеокарта.
  Выбор для большинства текстов.
- **LanguageTool** — для компьютера без видеокарты: на всех измеренных наборах находит в два–шесть раз меньше модели
  (в русском 3 из 18 против 18), зато без ложных тревог и для ~30 языков.
- **Harper** — то же для одного английского, ещё быстрее.
- **Корректор Edge** — для американского английского.
- По умолчанию работает одна проверка: в Tools → Grammar checking выбор одной выключает остальные. Последняя строка,
  **Several at once** (`grammarTogether`), разрешает несколько сразу, их находки показываются вместе.

Что LanguageTool добавляет рядом с моделью (по прогонам ниже, 6 октября 2026, текущая инструкция): на британском
академическом наборе — ничего, все 8 найденных им ошибок YandexGPT и Gemma 3 12B тоже нашли; на наборах с формулами —
ничего; на 69 предложениях — одну ошибку, которую пропустила YandexGPT («Who's book»), и три, пропущенные Gemma 3 12B
(«одела пальто», «If I would have known», «However I»). То есть это в основном второе мнение о том, что модель уже
нашла, изредка — лишняя находка, и никогда — ложная тревога. Там, где обе нашли одно место, редактор останавливается
на нём один раз (Shift+F7), а F7 показывает обе: исправление модели и объяснение LanguageTool, одно «Ignore» на обе.
Работа LanguageTool стоит 0,7–1 ГБ памяти и не требует видеокарты. Плагин для Obsidian выбрал «одну проверку за раз»;
здесь обе вместе по-прежнему можно включить, но одной модели достаточно.

Код, блоки кода и таблицы грамматикой не проверяются; разметка, адреса и пути от проверяльщиков скрыты.

**LaTeX** (`.tex`) с 6 октября 2026 проверяется так же. Текст — тело после `\begin{document}`; `\emph{…}`,
`\textbf{…}`, `\section{…}`, `\footnote{…}`, `\item` оставляют свой текст, команды и скобки скрыты; `\cite{…}`,
`\ref{…}`, `\eqref{…}`, `\label{…}` считаются формулами (находка, задевшая их, отбрасывается); `%`-комментарии скрыты;
`\%` — знак процента. Не текст: преамбула, `figure`, `table`, `tabular`, `verbatim`, `lstlisting` и подобные. Формулы:
`$…$`, `\(…\)`, `\[…\]` и выносные окружения (`equation`, `align`, `gather`… и со `*`), которые принадлежат
предложению вокруг, как блоки `$$` в Markdown: «We define $f$ by \begin{equation}…\end{equation} which **are**
continuous» — одно предложение. Заголовок (`\section{…}`) — отдельный абзац. Предложения стиля не предлагают правку,
которая потеряет команду LaTeX. Замер на `tools/proofbench/cases/tex-en.json` (11 ошибок, 8 правильных абзацев, полных
LaTeX): YandexGPT 5 Lite нашла 10 при 1 ложной тревоге (переписала `\textbf{Proof.}`), Gemma 3 12B — 10 без ложных,
LanguageTool — 4 без ложных. Для абзаца LaTeX-документа модели сказано переписывать LaTeX как есть; до этого Gemma
теряла две ошибки, зацикливаясь, когда переписывала LaTeX в свой ответ (`docs/tech/proofing-internals.md`).
**F7 → Ignore** на грамматической находке скрывает её до закрытия редактора: это правило на этом тексте, во всех
открытых файлах (то же слово скрыто везде, то же правило на других словах по-прежнему видно). **F7 → Never show this**
скрывает всё правило навсегда: правило (или
исправление) записывается в `ignoredRules` в настройках, для всех проверяльщиков; **Tools → Ignored rules…**
показывает их список, снятая галочка возвращает правило. Ненужное правило — например «Hence» → «Hence,»
(`SENT_START_CONJUNCTIVE_LINKING_ADVERB_COMMA`), частое в математических текстах, — отключается одним F7.

**Собственные правила LanguageTool** — в файле настроек: `languageToolDisabledRules`, `languageToolDisabledCategories`
(выключены), `languageToolEnabledRules` (включены правила, которые по умолчанию выключены), `languageToolLevel`
(`"default"` или `"picky"` — больше правил стиля). Словарные правила (`MORFOLOGIK_RULE_*`, `*_SPELLER_RULE`,
`HUNSPELL_*`) отбрасываются всегда: орфографией занимается её поставщик. По умолчанию выключены
`BRE_STYLE_OXFORD_SPELLING` (она ругает правильное британское -ise) и правила о повторных пробелах и начале
предложения — редактор заменяет разметку пробелами. Остальная категория `TYPOS` с 6 октября 2026 включена (нашёл
плагин для Obsidian): в ней же then/than, its/it's, dont → don't. Замер: английские предложения 14 → 19 из 25,
британский академический набор 8 → 9 из 24, формулы 5 → 7 из 20, русский без изменений, новых ложных тревог нет. Файл
настроек, где ещё записан старый набор по умолчанию (`TYPOS` и Oxford), читается как новый. Идентификаторы правил — те, что показывает LanguageTool
(строка сообщений в F7); полный список — на languagetool.org.

**Память**: `languageToolMemory` (куча Java), по умолчанию `"768m"`. Замер 6 октября 2026, 400 абзацев: русский и
английский — 51 с при 512m и 52 с при 1g; пять языков по очереди (ru, en, de, fr, es) — 534 с при 512m (сервер
занимался сборкой мусора), 202 с при 768m и 205 с при 1g. Ни один прогон не упал от нехватки памяти. Процесс при этом
занимает около 0,7–1 ГБ.

- **В русском лучше всех YandexGPT 5 Lite**: все 14 ошибок, включая трудные («одела/надела», «ложит»,
  «по приезду», «не разу»), на которых спотыкаются остальные. Лицензия — собственная Яндекса, для личного
  использования подходит.
- **В английском YandexGPT и Gemma 3 12B почти равны** (20 и 21 из 25), но ошибаются по-разному. YandexGPT не
  знает «Who's/Whose», «have seen yesterday», «Me and my sister» и запятую между двумя предложениями («I went to the shop, I bought»). Gemma пропускает запятые («However I…»), «If I would
  have known», «weather/whether» и запятую между двумя предложениями; ещё она правит правильное «Whom» на «Who».
- **Qwen3 14B** не лучше Qwen3 8B, а весит почти вдвое больше.
- **Маленькие модели** (Gemma 3 4B, Phi-4-mini) пропускают трудные случаи, иногда меняют смысл (Phi-4-mini:
  «что-бы он сказал» → «что он сказал») и иногда отвечают не тем: Phi-4-mini перевела три английских предложения на
  русский, Gemma 3 4B вернула посторонний текст. В редакторе такие ответы отбрасываются защитой от переписывания, но
  и ошибки в этих предложениях остаются ненайденными.
- **Корректор Edge** (модель Aion, только английский) по грамматике на уровне средних моделей (19 из 25), но
  проверяет по американским правилам: 4 из 6 его «ложных» — британское написание, исправленное на американское
  (organised → organized, centre → center, travelled, apologise). Для текстов на американском английском он был бы
  заметно лучше; для британского — нет. Модель небольшая (1,2 ГБ), но включается только скрытыми флагами Edge Canary.
- **LanguageTool** нашёл меньше всех: в русском исправил 3 («в течении», «одела», «не смотря») и ещё 3 заметил без
  верного исправления («Я пошли», «Мы был», «не разу»); в английском — 14 из 25. Зато ни одного ложного срабатывания
  и самый быстрый ответ. Опечатки в редакторе у него отключены — их ищет словарь Windows или Office.
- **«The committee have agreed»** все модели и Edge правят на «has»; в британском английском допустимы оба, так что
  это спорный случай. **«analyze»** (британское — «analyse») не исправил никто; его поймает словарь en-GB.

**Вывод:** для русского — YandexGPT 5 Lite, для английского — YandexGPT или Gemma 3 12B. Вместе с LanguageTool
(объясняет найденное, не ошибается) и словарём (опечатки) получается самый полный бесплатный вариант.

Выборка небольшая, результаты — ориентир, а не окончательный рейтинг. Замер можно повторить:
`python tools\proofbench\bench.py` при закрытом редакторе, корректор Edge — `tools\proofbench\edge.py`; ответы всех
проверяльщиков по каждому предложению — в `tools\proofbench\results.json`.

  you», а Gemma 3 12B в одном случае с формулой пропускает «the equation … have no real roots» (там 18 → 16 из 20;
  у YandexGPT 20 из 20). Ни Harper, ни LanguageTool эти два не ловят.
- **Написание** — дело словаря: словари en-GB Windows и Word ловят 7 из 8 (кроме «programme» в значении компьютерной
  программы — по-британски «program»), без ложных тревог.

**Для британских академических текстов:** YandexGPT 5 Lite или Gemma 3 12B и словарь en-GB Windows (или Word) для
написания; LanguageTool или Harper рядом ничего не стоят и ложных тревог не добавляют. Повторить:
`$env:BLUEEDIT_PROOF_BENCH='report.md'; dotnet test tests\BlueEdit.Tests --filter ProofBench` (docs/tech/proofing-internals.md, «Measuring»).

## Стиль

**Ctrl+F7** (или **Tools → Style suggestions**) на абзаце: языковая модель предлагает, как сказать лучше, — без
канцелярита, лишних слов и повторов, яснее. Это не исправление ошибок, а другая формулировка, поэтому ничего не
подчёркивается и ничего не меняется само:

```
Style (YandexGPT 5 Lite): 2 suggestions
  [x] Мы провели анализ данных и по ре… → Мы проанализировали данные и   — повтор, канцелярит
  [x] которые мешают → мешающие                                       — короче
  ─────────────────────────────────────
  Мы провели анализ данных и по результатам анализа данных выяснили
  → Мы проанализировали данные и выяснили
  (повтор, канцелярит)
```

Под списком — выбранное предложение целиком: было, стало, почему. **Пробел** снимает или ставит галочку, **Enter**
применяет отмеченные, **Esc** — ничего не менять. Применённое отменяется одним **Ctrl+Z**.

- Нужна языковая модель, как для грамматики: llama.cpp и модель здесь либо сервер моделей или облачный сервис (см.
  [proofing-setup.ru.md](proofing-setup.ru.md)); включать проверку
  грамматики не обязательно. Модель та же, что выбрана в **Tools → Grammar model…**, и в видеопамяти она одна на оба
  дела. Первый запрос запускает её (несколько секунд), дальше — около секунды на абзац.
- **Tools → Style options…** — что искать (галочками): канцелярит; многословие и слова-паразиты; повторы; длинные и
  запутанные предложения; страдательный залог, где действительный читается лучше; книжные слова, где подойдут
  простые; и, по умолчанию выключено, **разговорные слова в формальном тексте (академический стиль)** — «a lot of»,
  «really», «got», «kind of», сокращения — для эссе и статей. Ничего не отмечено — значит всё по умолчанию (кроме
  академического). Хранится в `styleFocus`.
- Модели сказано сохранять смысл, факты, имена, числа и термины, голос автора и язык текста, ничего не добавлять и не
  сокращать до пересказа. Если абзац хорош, ответ — «nothing to improve».
- Ещё модели сказано сохранять регистр (не вставлять сокращения в формальный текст), а для британского английского —
  британское написание и норму (-ise, -our, whilst, «the committee have»).
- Правки в одном предложении приходят одной: если модель переставила слова, она меняет несколько мест, которые имеют
  смысл только вместе, поэтому их принимают или оставляют вместе.
- Защиты: в британском тексте правка, которая только переписывает слова на американский лад (organisation →
  organization, behaviour → behavior), не предлагается — YandexGPT делала такие правки вопреки инструкции; если модель ответила на другом языке (с одним только «не переводи» модели переводили русский абзац на
  английский — теперь им прямо называется язык), ответ отбрасывается с сообщением; правка, которая потеряла бы
  разметку Markdown, ссылку или адрес, не предлагается.
- YandexGPT правит смелее: «В целях осуществления контроля за исполнением данного поручения необходимо произвести
  проверку документации…» стало «Нужно проверить документы…» — цель проверки пропала, так что смотрите, не ушёл ли
  смысл. Gemma 3 12B осторожнее («Чтобы проверить выполнение поручения, необходимо до пятницы проверить…»).
  Маленькие модели (Phi-4-mini, Gemma 3 4B) справляются хуже.

**Замер** 5 октября 2026 (`tests/BlueEdit.Tests/StyleBench.cs`) на 24 британских академических абзацах
(16 с 36 проблемами стиля, 8 хороших, часть с формулами) и 10 русских, с настройками по умолчанию:

| Модель | EN: проблем затронуто (36) | EN: потерян смысл | EN: хороших изменено (8) | RU: проблем (11) | RU: потерян | RU: хороших изменено (4) | Ответ |
|---|---|---|---|---|---|---|---|
| **Gemma 3 12B** | 33 | 1 | 3 | 10 | 0 | 2 | 1,8 с |
| Qwen3 8B | 32 | 0 | 4 | 11 | 2 | 2 | 1,3 с |
| YandexGPT 5 Lite | 30 | 3 | 6 | 11 | 1 | 3 | 1,4 с |

«Потерян смысл» — если принять все правки, пропадает факт, термин, формула или британское написание, которые абзац
должен сохранить. До строк о регистре и британской норме (те же наборы): YandexGPT теряла смысл в 5 английских
абзацах и меняла 7 хороших 15 правками («organisation analysed … behaviour» на американский лад, «cannot» → «can't»),
Gemma — 2, Qwen3 8B — 1; русский не изменился. **Для стиля британского английского надёжнее Gemma 3 12B** (или
Qwen3 8B); YandexGPT всё ещё выбрасывает части фраз («to answer this question», «with regard to funding») и правит
«the committee have». С академической опцией все модели ловят и большую часть разговорных слов (11–12 из 13).

## Настройки в файле

**Tools → Settings…** показывает основные настройки списком; его последний пункт, **Edit settings.json…**, открывает `%APPDATA%\blueedit\settings.json` (в Linux
`~/.config/blueedit/settings.json`) со всеми настройками; F2 сохраняет и сразу применяет, Esc возвращает к тексту.

```jsonc
"spellCheck": true,                     // орфография вкл/выкл (то же, что F8)
"spellLanguages": "auto",               // или ["ru-RU", "en-GB"]
"spellProvider": "windows",             // или "office", "hunspell"
"grammar": ["languagetool", "llm"],     // "off", "languagetool", "llm", "harper", "edge", "chrome", "chromemodel" или список
"languageToolDir": "",                  // пусто: %LOCALAPPDATA%\BlueEdit
"llmDir": "",                           // пусто: %LOCALAPPDATA%\BlueEdit\llm
"llmModel": "",                         // пусто: лучшая из установленных (Tools → Grammar model…)
"edgePath": "",                         // пусто: Edge Canary
"styleFocus": ["officialese", "wordiness", "repetition", "clarity", "active", "simple"]   // что искать в стиле; + "informal" для академических текстов
```

Каждая настройка должна встречаться в файле один раз.

## Как проверить, что всё работает

Откройте файл `.md` с таким текстом:

```
Превет, это проверка орфографии.
Я пошли домой вчера. Мы был в магазине и купили хлеб.
Он сказал что придёт завтра.
This sentense have two errors.
The results was good, and I recieved them yesterday.
```

Что должно получиться:

1. **Превет**, **sentense**, **recieved** подчёркнуты как опечатки; F7 показывает варианты под заголовком `"Превет" — Windows spelling`.
2. **Я пошли**, **Мы был**, **сказал что**, **have**, **results was** — грамматика, подчёркнута другим цветом
   через 1–3 секунды (при первом запуске — дольше). Что именно найдётся, зависит от проверяльщика: модель обычно
   находит всё, LanguageTool — часть и не всегда с исправлением.
3. Shift+F7 обходит все ошибки по порядку, в строке состояния видно, кто нашёл каждую.

Если грамматика молчит — посмотрите строку состояния: `GRAMMAR … failed` значит, проверяльщик не запустился
(обычно не хватает файлов); **Tools → Grammar checking…** покажет, чего не хватает.
