# Языковые серверы: ошибки и предупреждения в коде

*In English: [lsp.md](lsp.md)*

BlueEdit общается с **языковыми серверами** — теми же программами, что использует VS Code и другие редакторы
(протокол Language Server Protocol), — и показывает ошибки и предупреждения в коде прямо при наборе. Серверы бесплатные,
ставятся один раз, всё работает на вашем компьютере.

Что уже работает:

- ошибки подчёркиваются цветом опечаток, предупреждения — своим (цвет темы `warning`);
- **Shift+F7** переходит к следующей (вместе с опечатками и грамматикой), в строке состояния — что это:
  `Error (Pyright): "undefined_name" is not defined`;
- **F7** на ней предлагает исправления сервера, его предпочтительное первым — у csharp-ls: недостающий `using`,
  создать тип… — Enter применяет (один шаг отмены; исправление, задевающее другие файлы, открывает их, как
  переименование). Последняя строка, а также F7 там, где у сервера исправлений нет, показывает полный текст
  сообщения. pyright исправлений не предлагает (измерено: для неопределённого имени — ни одного), поэтому в Python
  F7 показывает сообщение;
- в строке состояния — сервер файла и счётчики: `LSP pyright-langserver 2E 1W`
  (`starting` — запускается, `failed: …` — не запустился, с причиной);
- **дополнение от сервера**: после точки сам открывается список членов (`os.` → `path`, `sep`…; `s.` → `Length`…),
  справа — вид: `m` метод, `f` функция, `fld` поле, `prop` свойство, `var` переменная, `cls` класс, `mod` модуль,
  `kw` ключевое слово, `const`…; после трёх букв слова варианты сервера идут первыми; **Ctrl+Space** спрашивает сервер
  (ждёт не дольше 0,4 с, а пока сервер запускается — не ждёт вовсе), иначе берёт слова из текста. Набор никогда не ждёт: вопрос уходит в фоне, а список
  открывается, когда пришёл ответ, если курсор за это время не ушёл. **Tab** берёт выбранное; Enter — только после
  выбора стрелками.

- **F12** — к определению символа под курсором, в этом файле или другом (он откроется во вкладке); если определений
  несколько — выбор из списка. **Shift+F12** — обратно туда, откуда прыгнули (сколько угодно шагов назад).
- **Alt+F1** — что сервер знает о символе под курсором: тип или сигнатура и документация.
- **Ctrl+F12** форматирует файл (или Format → Format code). Один шаг отмены (Ctrl+Z); форматируется текст на экране,
  сохранён он или нет. Кто форматирует:
  - **языковой сервер**, если у него есть форматировщик: у csharp-ls есть (Roslyn: отступы, пробелы, скобки, но
    однострочный блок остаётся на одной строке). С выделением — только выделенные строки.
  - **программа-форматировщик** иначе: у pyright форматировщика нет, поэтому для Python — **ruff**, а если его нет —
    **black**. Она запускается в папке файла и знает его путь, поэтому действуют настройки проекта (`pyproject.toml`,
    `ruff.toml`: длина строки, кавычки…). Форматирует весь файл, и с выделением тоже. При синтаксической ошибке
    текст не меняется, а в строке состояния — сообщение программы.
  - Ни того, ни другого: строка состояния так и говорит (`no formatter: Tools > Code tools installs ruff`).

  Поставить ruff: **Tools → Code tools** или `tools\lsp-setup\install.ps1 -Python` (winget, `astral-sh.ruff`, для текущего пользователя) или
  `tools/lsp-setup/install.sh --python` (релиз ruff с GitHub в `~/.local/bin`). black, поставленный через
  `pip install --user black`, тоже находится, хотя pip не добавляет его папку в `PATH`.
- **Ctrl+F2** переименовывает символ под курсором везде, где его находит сервер (или Edit → Rename symbol). Наберите
  новое имя (оно заменит старое) и Enter. Открытые файлы получают изменение одним шагом отмены каждый; неоткрытые
  открываются с изменением, **несохранёнными**, чтобы было видно, что поменялось, — **File → Save all** записывает их.
  В строке или комментарии редактор сразу говорит, что переименовывать нечего, не спрашивая имени. Переименовывают и
  pyright, и csharp-ls.
- **Alt+F12** — где используется символ под курсором: его определение и все использования, известные серверу, во всех
  файлах (или Search → Symbol references). Список показывает каждое место с его строкой и начинается с того, что под
  курсором; Enter открывает файл в этом месте. **Search → Folder results** снова открывает последний список. Находят
  использования и pyright, и csharp-ls.
- **Ctrl+O** в коде — структура файла от сервера: классы, функции, методы, свойства, вложенные как в файле, с их
  видом; то, что внутри функции (её локальные переменные), не показывается. Enter переходит туда. В Markdown и LaTeX
  Ctrl+O, как и раньше, показывает заголовки. Проверено с pyright; csharp-ls это тоже умеет.
- **Параметры при вызове**: после `(` и `,` в строке состояния — сигнатура функции, текущий параметр в скобках:
  `greet([name: str], times: int = 1)`; держится, пока курсор на этой строке, `)` или переход на другую строку
  убирают её. Запрашивается в фоне, как и всё остальное.

## Серверы

**Проще всего: Tools → Code tools** (или `be --install-tools` в командной строке, в том числе по SSH). Редактор
ставит их в свою папку — `%LOCALAPPDATA%\BlueEdit\tools` на Windows, `~/.local/share/blueedit/tools` в остальных
системах (`BLUEEDIT_TOOLS` её переносит) — без прав администратора и системных пакетов и сам их там находит:

| Инструмент | Для чего | Ставится вместе с | На диске (измерено) |
|---|---|---|---|
| pyright | Python: ошибки, дополнение, определения, переименование… | Node.js (текущая LTS, с nodejs.org) | 250 МБ на Linux, 120 МБ на Windows |
| ruff | Python: форматирование | — (одна программа, из релизов на GitHub) | 23 МБ |
| csharp-ls | C#: ошибки, дополнение, исправления… | .NET SDK 10 (из списка выпусков Microsoft) | 720 МБ |
| typescript | JavaScript, TypeScript: ошибки, дополнение, определения, переименование… | — (TypeScript 7, одна родная программа, из реестра npm) | 27 МБ |

Окно — таблица инструментов: каждый найден (и где: уже лежащий в `PATH` используется как есть), установлен здесь или
что займёт его установка; под ней кнопки **Install the missing** (поставить недостающее), **Remove what was installed
here** (удалить папку) и **Close**. Всё идёт в фоне, шаги — в строке состояния, а по окончании запускаются серверы.
`be --install-tools pyright,ruff` ставит только названные. Node.js и ruff сверяются с суммами SHA-256, которые
публикуют их проекты, .NET SDK — с SHA-512 из списка выпусков Microsoft, TypeScript — с SHA-512 из реестра npm; что пошло не так — в `install.log` в той же папке.

Файл Python, C#, JavaScript или TypeScript, для которого сервер не установлен, один раз говорит об этом: `Python: no language server installed
…: Tools > Code tools`.

Серверы вручную, если так удобнее:

| Язык | Сервер | Установка |
|---|---|---|
| Python | pyright (Microsoft, MIT) | `npm install -g pyright` (нужен [Node.js](https://nodejs.org)) |
| C# | csharp-ls (MIT) | `dotnet tool install -g csharp-ls` (нужен .NET SDK) |
| JavaScript, TypeScript | собственный сервер TypeScript 7, `tsc --lsp --stdio` (Microsoft, Apache-2.0) | только Tools → Code tools: редактор запускает свою копию по полному пути, потому что `tsc` в `PATH` — обычно TypeScript 5 из npm, где сервера нет. Другой можно указать в `languageServers` |

Или `tools\lsp-setup\install.ps1 -All` — ставит или обновляет оба; без ключей показывает, что BlueEdit находит.
Если нет Node.js или .NET SDK, скрипт предложит поставить их через winget (`OpenJS.NodeJS.LTS`,
`Microsoft.DotNet.SDK.10`) — на весь компьютер, поэтому Windows спросит разрешения администратора; `-Yes` ставит без
вопроса. Если winget нет, скажет, что поставить вручную.

Сервер используется, если его команда находится — в `PATH` (с `.cmd`/`.exe`) или в `%USERPROFILE%\.dotnet\tools`, куда
ставятся dotnet-инструменты. Если сервер не установлен, он просто не используется, без сообщений.

**Linux (и WSL)**: `tools/lsp-setup/install.sh --all`. pyright ставится через npm в `~/.local` (`npm install -g`
потребовал бы root), csharp-ls — в `~/.dotnet/tools`; если нет Node.js или .NET SDK, скрипт предложит поставить их через
apt (`nodejs npm`, `dotnet-sdk-10.0`; sudo спросит пароль, `--yes` — без вопроса). Linux-версия ищет сервер в `PATH`, в
`~/.local/bin` и в `~/.dotnet/tools`; под WSL папки Windows из `PATH` (`/mnt/c/…`) пропускаются — npm-обёртки там
выглядят исполняемыми, но требуют Node из Windows. Проверено в WSL (Ubuntu 24.04): pyright 1.1.414 и csharp-ls 0.28.0,
тесты с настоящими серверами проходят.

## Как устроено

- Когда показан файл языка с сервером, сервер запускается (один на язык и **корень проекта**) и останавливается вместе с
  редактором — задание Windows (job object) закрывает его, даже если редактор убит.
- Корень проекта — ближайшая вверх папка с признаком: C# — `*.sln`, `*.slnx`, `*.csproj`; Python — `pyproject.toml`,
  `pyrightconfig.json`, `setup.py`, `setup.cfg`, `requirements.txt`; JavaScript и TypeScript — `tsconfig.json`,
  `jsconfig.json`, `package.json`; для любого языка — `.git`; иначе папка самого
  файла. Для полной проверки C# нужен проект: одиночный `.cs` проверяется слабо.
- Текст файла уходит серверу после каждой правки (не чаще двух раз в секунду, из фонового потока), в том числе
  несохранённый: находки соответствуют тому, что на экране, а не на диске. Набор сервер никогда не задерживает.
- Находки приходят, когда сервер их готов отдать; экран обновляется сам. Сервер, который отвечает только на вопрос
  (находки «по запросу» из LSP 3.17, так делает TypeScript 7), спрашивается после каждой правки, а если он говорит,
  что ошибки одного файла зависят от другого, то и про остальные открытые файлы.

## Настройки

```jsonc
"lsp": true,                                   // false — без языковых серверов
"languageServers": {                           // поверх стандартных
    "Python": { "command": "pylsp", "args": [] },                // другой сервер для языка
    "C#": "off"                                                   // стандартный выключен
},
"formatters": {                                // Ctrl+F12 программой, раньше форматирования сервера
    "Python": { "command": "black", "args": ["-q", "--stdin-filename", "{file}", "-"] },
    "C#": "off"                                                   // без форматирования для языка
}
```

Форматтер читает текст со стандартного входа и пишет отформатированный; `{file}` в его аргументах — путь файла.
Подойдёт любая такая программа: `prettier --stdin-filepath {file}`, `clang-format --assume-filename={file}`…

Названия языков — как в строке состояния: `Python`, `C#`, `PowerShell`, `C/C++`, `JavaScript`, `Go`, `Rust`, `Java`,
`JSON`, `SQL`, `HTML/XML`. Подойдёт любой сервер, работающий по LSP через stdio (clangd для C/C++, gopls для Go,
rust-analyzer для Rust…); проверены Python и C#. Сервер PowerShell (PowerShell Editor Services) запускается длинной
командой и пока не настроен.

## Если не работает

| Строка состояния | Причина |
|---|---|
| нет `LSP …` у файла .py / .cs | сервер не установлен или не найден: `tools\lsp-setup\install.ps1`; или `"lsp": false`, или язык `"off"` |
| долго `LSP … starting` | сервер сначала загружает проект: csharp-ls запускает MSBuild (от секунд до минуты на большом решении) |
| `LSP … failed: …` | не запустился или не ответил на `initialize` за 60 с; дальше — причина (и один раз в строке сообщений) |
| `LSP … stopped: …` | сервер завершился; дальше — последняя строка, которую он написал в поток ошибок |

Тесты: `tests/BlueEdit.Tests/LspTests.cs` (пути, корни, настройки, отрисовка; настоящие pyright и csharp-ls, если
установлены), `tests/ui/test_lsp.py` (pyright в настоящем редакторе). Как устроено: `Lsp/LspClient.cs` (JSON-RPC через
stdio с заголовками Content-Length; на запросы сервера отвечает пустыми результатами), `Lsp/LanguageServers.cs`
(серверы по языку и корню, синхронизация, находки), `EditorView.Diagnostics.cs` (подчёркивания, Shift+F7, F7).
