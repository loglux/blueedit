# Пакеты для Linux: .deb и .rpm (`tools/packages`)

English: [packages.md](packages.md).

В каждом релизе, кроме tar.gz, есть `blueedit_<версия>_amd64.deb` (Debian, Ubuntu и подобные) и
`blueedit-<версия>-1.x86_64.rpm` (Fedora, RHEL и подобные); ставятся средством самой системы:
`sudo apt install ./blueedit_…deb`, `sudo dnf install ./blueedit-…rpm` ([docs/linux.ru.md](../linux.ru.md)).

## Что внутри

| Где | Что |
|---|---|
| `/usr/lib/blueedit/be` | редактор, тот же файл, что в tar.gz |
| `/usr/bin/be` | ссылка на него: `be` в PATH |
| `/usr/lib/blueedit/mathimages/` | модуль картинок формул: там, где редактор ищет его первым делом, рядом с собой |
| `/usr/lib/blueedit/tools/…/install.sh` | скрипты установки проверок и языковых серверов, как в tar.gz (`.ps1` не берутся) |
| `/usr/share/doc/blueedit/copyright` | лицензия (MIT) |

Папки редактора принадлежат пакету (перечислены как каталоги), поэтому удаление пакета убирает и их: `dnf remove` на
Fedora сначала оставлял пустой `/usr/lib/blueedit` — rpm удаляет только папки, которыми пакет владеет.

Почему `/usr/lib/blueedit` и ссылка, а не файл в `/usr/bin`: модуль и скрипты лежат рядом с редактором, а в `/usr/bin`
место только программам. Через ссылку редактор всё равно находит модуль: .NET берёт свою папку по настоящему файлу
(`/proc/self/exe`), а не по ссылке; проверяет `probe.py` (ниже).

Модуль внутри пакета, а не отдельным пакетом: установщик для Windows тоже ставит его по умолчанию, а весит он 14 МБ
рядом с 76 МБ редактора.

**Ни от чего не зависит.** Редактор самодостаточный (.NET внутри). То, чем он пользуется, если оно есть, —
рекомендуется, и apt с dnf ставят это по умолчанию: корневые сертификаты и OpenSSL (загрузки по https; без них окно
говорит, что поставить) и ICU (названия языков; без неё — инвариантный режим .NET). Debian называет библиотеки по
версии, поэтому в .deb — варианты (`libicu76 | libicu74 | libicu72`, `libssl3t64 | libssl3`); в .rpm — `libicu`,
`openssl-libs`, `ca-certificates`. Что редактор делает без каждого, сказано в docs/linux.ru.md.

## Как собираются

`tools/packages/nfpm.yaml` описывает оба; `tools/packages/build.py ВЕРСИЯ СБОРКА_LINUX МОДУЛЬ ПАПКА` подставляет пути и
версию и запускает [nfpm](https://github.com/goreleaser/nfpm) (одна программа, MIT; делает и .deb, и .rpm без dpkg и
rpm, поэтому и на Windows-машине релиза). nfpm 2.48.0 скачивается с его релиза на GitHub при первом запуске, и его
SHA-256 сверяется с записанной в `build.py` (из `checksums.txt` того релиза) — так же, как скрипты установки делают с
Node.js и ruff. nfpm оставлял `${…}` в путях файлов как есть (подставляет их только в некоторых полях), поэтому
`build.py` подставляет значения в копию файла сам.

Workflow релиза запускает его после tar.gz и модуля, с той же сборкой для Linux, и прикладывает оба пакета с их
SHA-256. Здесь: `tasks packages` (в `publish-packages\`), затем `tasks packages-test`.

## Проверено

`tasks packages-test` (`tools/packages/test.sh`) копирует их на Linux-хост с Docker (`BLUEEDIT_LINUX_HOST`) и в
чистых контейнерах Debian 12, Ubuntu 24.04 и Fedora 41 ставит каждый через apt или dnf, запускает `be --version`,
запускает `be` в псевдотерминале и выключает и включает View > Formula pictures (`probe.py`: редактор говорит, что
модуль нашёлся), удаляет пакет и ищет, не осталось ли чего. 24 октября 2026 все три прошли: поставилось, модуль
нашёлся, ничего не осталось; apt поставил `ca-certificates`, `libicu72` и `libssl3` на Debian, `libicu74` и
`libssl3t64` на Ubuntu; на Fedora все три уже были.

Не проверено: установка новой версии поверх старой (должна заменить файлы; двух версий для пробы ещё нет), другие
дистрибутивы (openSUSE тоже берёт .rpm, не пробовали), arm64 (сборки для него нет).

## Не сделано

- **Обновления через `apt upgrade` и `dnf upgrade`**: для них нужен свой репозиторий пакетов (ключ подписи, файлы
  индекса, хостинг вроде GitHub Pages). Пока новая версия ставится так же, поверх старой.
- **Собственные репозитории дистрибутивов**: они собирают из исходников по своим правилам; не сейчас.
- **Snap и Flatpak**: в песочнице они видят файлы пользователя только через порталы; консольному редактору, который
  открывает любой данный ему файл, это не подходит.
- **winget и Scoop** (Windows) — следующие; план — в задаче, которая ведёт пакеты.
